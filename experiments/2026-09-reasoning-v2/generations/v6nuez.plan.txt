This screen is an **Explorer** pattern designed for a payments analyst to resolve a backlog of failed payouts. It prioritizes speed and context, allowing the user to quickly scan issues, apply filters, and take immediate corrective actions without leaving the view.

The layout features a **Header** with the current date, total failure count, and primary actions like "Export Log" or "Clear All." Below is a **FilterBar** enabling filtering by currency, failure reason, amount, and date range. The core of the screen is a **DataTable** displaying the failed transactions, with columns for Transaction ID, Amount, Currency, Failure Reason, Timestamp, and Status. The table includes row selection and a **BulkActions** bar to apply common fixes (e.g., "Retry All Selected") to multiple records at once. Each row is clickable, opening a modal **Drawer** as an **Inspector** to show detailed context, related user info, and specific error logs for deep investigation. The design ensures high-visibility status indicators (e.g., red for critical failures) and clear differentiation between resolved and active items.
