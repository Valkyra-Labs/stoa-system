This screen is a **ReviewQueue** designed for a payments operations analyst to manually resolve a backlog of failed payouts. The layout prioritizes sequential, focused work. It features a fixed sidebar listing all failed transactions with status badges (e.g., "Refused," "Timeout"). The main area displays one transaction at a time in a detailed **Inspector** view, showing the failed reason, customer details, and transaction metadata. Above this, a compact **FilterBar** allows the analyst to narrow the queue (e.g., "Show only refused"). Below the detail view, a **BulkActions** bar appears only when multiple items are selected, offering options like "Requeue All." A **Status** indicator at the top shows progress (e.g., "42 pending, 5 resolved"). The design minimizes context switching by keeping navigation and the current task front and center.
